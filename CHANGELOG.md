# Changelog

## 2026-10-18

- `engine/utils/pixelFormat.lua`: the format working canvases are made in, and reading one back safely. love.js offers no `rgba8` canvas, so LÖVE's `"normal"` lands on `rgba4` there, which bands every blurred gradient — and `ImageData:encode` has no encoder for it, which does not raise a Lua error but aborts the process and takes the game down with it. `newCanvas` picks `rgba8`, then `srgba8`, then `normal`; `toImageData` undoes the sRGB encode the hardware applies on write, so a read-back matches what was drawn. On desktop `"normal"` already is `rgba8`, so nothing changes there. `PostProcessing` and `AssetExporter` now go through it — `AssetExporter` encodes a canvas to PNG, which is exactly the call that aborts.
- `cacheManager.preloadFont(key, nil, size, hinting)` loads LÖVE's built-in font. A game that has not chosen a typeface yet, or only wants one for debug text, no longer needs a .ttf in the repo to satisfy the four font-key contracts.
- `love.directorydropped` is forwarded to the current scene's optional `directorydropped(path)`, matching `filedropped`. `Game:initializeEvents` owns every `love.*` callback, so a game could not otherwise take this one without fighting the engine for it.
- `Game:resize` now calls the current scene's optional `resize(w, h)` after resizing the post-processing canvases. Scenes that lay themselves out against the window had no way to hear about it.

## 2026-10-17 (device file picker and camera)

- `engine/device/`: one API for two things stock LÖVE cannot do on any platform. `filePicker.open(opts, callback)` shows the device's own picker and delivers the chosen file as a drawable `love.Image`, as raw bytes, or written into the save directory, because different games want different things; `engine/device/camera.lua` (required as `deviceCamera`, never `camera` — `engine/Camera.lua` is the 2D viewport) streams the device camera into one reused texture and takes stills. Both follow `saveManager`'s posture: a missing picker, a denied camera or a corrupt file arrive through the callback, never as an error. See `docs/device.md`.
- Callbacks fire exactly once and never from inside `open`/`start`, not even for `"unavailable"`, so every call site has one code path; the request is cleared before the callback runs, so a callback may start the next one. `getState()` exposes `"awaitingGesture"`, which browsers force on us: they will not open a dialog or grant a camera except from a player's tap, so web arms the request and the page shows a button.
- Backends (`engine/device/backends/`) deal only in bytes and platform mechanics; config, delivery conversion, the texture and the callbacks stay in the front ends, so a new platform is one file. `null.lua` is both the contract and the fallback — a backend that fails to load or omits a function degrades to `isAvailable() == false` rather than erroring at the call site. The `web`, `desktop` and `mobile` backends are not written yet, so every real platform currently reports unavailable.
- `mock.lua` is a deterministic device: a 64x64 checkerboard PNG for picks and stills, colour-bar camera frames paced by the requested fps. `examples/runner/harness.lua` forces it for every example, so `scripts/test.sh` and CI cover the whole public API — open/cancel ordering, all three delivery modes, frame pacing, texture reuse, capability degradation — on machines with no camera. New `device` examples category with `device/file-picker` and `device/camera-preview`.
- **Fixed: the web build froze a few seconds after loading.** `scripts/web/index.html` dispatches a synthetic `beforeunload` every ten seconds to force love.js to flush the IndexedDB-backed save directory, and LÖVE answers it by running `love.quit`. A falsy return from `love.quit` lets the quit proceed and ends the main loop, and `engine/Game.lua` both returned nothing from `Game:quit` and discarded its result in the `love.quit` callback — so every web build stopped running at the first flush. `Game:quit` now returns true on web to refuse the quit (the flush is love.js's own listener and happens regardless), the callback passes the return value through, and the scene's `onQuit` autosave still runs, which is what the flush exists to persist. This predates the device work; it only surfaced because a frozen game stops reading the camera.
- Web file picker and camera (`engine/device/backends/web.lua`, `engine/device/webBridge.lua`, `scripts/web/index.html`). love.js exposes no `js` module, no `ccall` and no `FS`, so the bridge is built from what the runtime does export: Lua sends `key=value` commands to a `/dev/spooki` character device created with `FS_createDevice` (with a `Module.print` sniffer as a fallback needing no exports at all), and the page answers with files under `/tmp/spooki/` written via `FS_createDataFile` and read with plain `io`. `/tmp` and not the save directory, or the ten-second flush would copy every camera frame into IndexedDB. Camera frames are raw RGBA behind a sixteen-byte header, so an unchanged frame costs one tiny read and never an image decode.
- Browsers refuse to open a dialog or grant a camera outside a real user activation, and a command from the game arrives inside the wasm main loop, which is not one. So a web request is *armed*: `getState()` reports `"awaitingGesture"`, a full-screen overlay appears, and the dialog opens from the player's tap. Web file import costs one extra tap; `getCapabilities().needsGesture` is how a game words its prompt. `scripts/release.sh` now fails the build if the page lost the bridge or love.js stopped exporting `FS_createDevice`/`FS_createDataFile`, and `INITIAL_MEMORY` is 32 MiB because growing the heap copies the whole buffer.
- Desktop file picker (`engine/device/backends/desktop.lua`): the platform's own dialog — `osascript` on macOS, a Windows Forms `OpenFileDialog` through PowerShell with the `-STA` the dialog requires, `zenity` or `kdialog` on Linux. Nothing to install, nothing to bundle. Each dialog blocks for as long as the player browses, so it runs in a `love.thread` (`engine/device/threads/pickerThread.lua`, the repo's first use of threads) which also reads the file and checks `maxBytes` before reading, keeping both the dialog and a large read off the main thread. One thread per pick, exiting when it has answered: a pick is rare and player-initiated, so this costs nothing and avoids the stale-worker and hot-reload-leak problems a persistent worker brings.
- Drag and drop: `love.filedropped` is wired up (it was unwired) and a dropped file answers an open pick, so a player can drag a picture in instead of browsing. When no pick is waiting, or `allowDrop` is off, the drop falls through to the scene's optional `filedropped` hook. `love.threaderror` is wired up too — also previously unwired, which would have made a dead worker a silent hang — so a lost thread fails its request with a message.
- `SPOOKI_DEVICE_BACKEND` overrides the `device.backend` config, which is how a real backend is driven from the examples catalogue (it otherwise forces `mock`): `SPOOKI_DEVICE_BACKEND=desktop love . --example device/file-picker`. Nothing in the test suite sets it.
- `engine/utils/system.lua` grew from `isWeb()` to `getOS`/`isWeb`/`isMobile`/`isDesktop`; `engine/cacheManager.lua` gained `addImage`, `replaceImage` and `hasImage` so an imported or captured image can be cached (`preloadImage` loads from a path and refuses a duplicate key, which imports do constantly). `Game` takes a `device` config block, selects the backend before scenes load, pumps both modules in `update` and stops the camera on quit.

## 2026-10-02 (examples and tests)

- Examples catalogue and regression suite: 47 runnable scenes under `examples/<category>/<slug>.lua` across scenes, game objects, animation, camera, input, UI, collision, lighting, post-processing, utilities and saves. `love . --examples` opens a picker, `love . --example <id>` runs one with hot reload, and `scripts/test.sh` drives every example for 120 frames at a fixed dt with scripted input, per-example `check` assertions and golden screenshots in `examples/__snapshots__/` (also the thumbnails at https://spookidev.com/spooki-love/examples). `.github/workflows/ci.yml` runs it on push and pull request. See `examples/README.md` and `docs/examples.md`.
- `main.lua` hands over to `examples/runner` between `-- examples:begin` / `-- examples:end`; `init.sh` strips the block and the examples tooling from scaffolded games; `scripts/release.sh` excludes `examples/`; `scripts/lint-lua51.sh` builds Lua 5.1 with the `generic` target off macOS.
- Engine fixes found by the suite: `GameObject:destroy()` destroyed only every second child (it iterated the list each child removed itself from); `inputMap.resetToDefaults(name)` crashed for a single action (the assert message joined the list); Theta* recorded the wrong predecessor when there was no line of sight, so paths could cut through walls; the vendored Shädows library could never be required (it registered itself only as `shadows`, not `engine.lib.shadows`) and `LightWorld:GetColor` returned blue and alpha swapped; scene draw order now breaks ties on object name so equal-priority objects render in a stable order.
- `notify-site.yml` also tells the site to rebuild when examples or engine code change.

## 2026-10-02

- Documentation rewritten as nine pages under `docs/` (getting started, scenes, game objects, UI, input, engine, assets, build and release, development), each with `title`/`description`/`order` frontmatter so https://spookidev.com/spooki-love/docs can render them. The old `CreatingANewScene.md`, `UiComponents.md` and `features.md` are folded in. `.github/workflows/notify-site.yml` tells the site to rebuild when `docs/**` changes on `main` (needs the `SITE_DISPATCH_TOKEN` secret).
- Action-based input (`engine/input/inputMap.lua`): named actions with keyboard, mouse and gamepad bindings, analog strength, `axis`/`vector` composition, per-frame edges and `onActionPressed`/`onActionReleased` events, single player on any device. Custom bindings persist to `bindings.lua` in the save directory.
- Button prompts: Kenney Input Prompts Pixel 16× (CC0) in `assets/graphics/input-prompts.png`, indexed by `engine/input/glyphs.lua`; `engine/ui/InputPrompt.lua` shows an action's bindings for the active device.
- Menus with a gamepad: `engine/ui/FocusGroup.lua` and focusable `Button`s driven by the built-in locked `ui_*` actions; the Menu is navigable and gains a Controls button.
- `scenes/Controls.lua` rebinding screen, listing whatever actions `main.lua` declares.
- `UIText` accepts percentage widths; hidden objects no longer receive clicks; the unused `engine/InputManager.lua` is gone.
- `engine/saveManager.lua`: single-slot save file in the save directory, serialised as Lua source; `save`/`load`/`exists`/`delete` never throw, saves carry a schema `version` with an optional `migrate` hook. `Game:quit` now calls the current scene's optional `onQuit()`; `sceneManager.addScene`/`resetScene` return the instance and `getScene(name)` was added.
- Engine fixes: `State:reset()` restores the defaults (the initial table is deep-copied; before, `set` mutated it), `table_serialize.deserialize` uses `loadstring` so it runs under PUC Lua 5.1, rejects non-finite numbers and emits sorted keys, and `utils/table.lua` gains `deepCopy` and a working `getTableSize`.
- `conf.lua` sets `t.identity = "newgame"` (rewritten by `init.sh`) so saves share one directory between source runs and builds; `scripts/web/index.html` flushes the IndexedDB save directory on `pagehide`, tab hide and every 10 s.
- `init.sh` scaffold wizard: copies the template into a new directory (or renames a clone in place), asks for title/author/itch.io username, and rewrites the window title, wordmarks, release variables, README and changelog. `scripts/release.sh` excludes it from the `.love`.
- Lua 5.1 compatibility for the love.js web build: `UIBox` layout loops no longer use `goto` (PUC Lua 5.1 rejects it, so the browser build crashed on load).
- `scripts/lint-lua51.sh` parses Lua with a real `luac` 5.1 (built once into `~/.cache/love-release/`); `.githooks/pre-commit` and `scripts/release.sh` run it, and `.luarc.json` now targets Lua 5.1 so the editor flags the same errors.
- Bare web page template in `scripts/web/` replaces the stock love.js page (no heading, footer or "Powered by" text); the release checklist explains the itch.io browser-play flag.
